# 孙学主题：资源决策与需求验证

输入以用户的真实目标和约束为准，已有上下文能回答的无需重问。

## 形成选择

先弄清要解决的问题，以及不行动的代价。列出少量真正不同的候选，其中可以包括维持现状。比较前固定用户关心的标准，避免喜欢某个选项后临时改标准。

在表中列出时间成本、现金成本、预期用途、关键不确定性与证据；信息没有核实时标未知。若用户要求最新价格、机会或市场，查原始来源并标核对日期。没有联网也可以做框架，但不假装已验证市场。

候选多时先筛选；无需机械看 100 个。给探索设置投入上限，并为优先候选设计一个可以退出的实验。

## 判断商业想法

把“趋势很大”改写成可验证的假设：谁遇到什么问题，现在如何解决，为什么现有方式不够，用户能提供什么不同价值？

可选择的交付：一个可运行小样、一页问题说明、公开反馈归纳，或一份用户访谈提纲。真实客户的使用或付费意向与模型对市场的推测分别记录。不得伪造访谈、预约或收入；不要把 API 价差或服务转售自动当成可执行商业方案。

投资研究与职业选择分别处理。讨论机会不默认开启交易、购买、开户或资金配置；相关规则与具体建议需要按实际任务核验来源。

## 推荐输出

| 候选 | 为什么可能适合 | 成本与限制 | 还缺什么证据 | 最小验证 |
|---|---|---|---|---|

最后选一个本轮最值得验证的方案，写明试验结果如何改变判断。若现有材料只支持缩小问题，就交付问题澄清，不强行给肯定结论。
