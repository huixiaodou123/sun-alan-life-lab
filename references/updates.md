# 新观点的自动检查与增量更新

## 什么时候运行

用户开始一个新的应用任务，或说“更新”“最近又说了什么”时，先轻量检查孙宇晨、邵艾伦本人最新公开内容。当前会话已经检查过就承接结果，不反复刷同一批材料。解释一个历史概念时无需刷新；用户要求离线、先做事或不联网时遵从。

这由当前 Agent 在调用 Skill 时执行，不是文件自身在后台常驻。不把“尚未配置定时监控”说成已实现即时推送。用户以后明确要定时监控，再按其工具和授权部署。

## 检查与判断

1. 读取 [sources.md](sources.md) 的本人主页、原片及账号归属；优先本人最新发布，不把热搜二创当本人新观点。有平台工具就读取本人最近少量作品/文字；否则用公开原始网页。孙宇晨公开账号 `sunyuchentron`、邵艾伦公开账号 `AlanShao111`；抖音本人主号和关联小号见来源登记。渠道失败则换可访问的本人渠道；本轮仍受阻就记范围，继续用户当前任务，不要求用户先补一套资料。
2. 与 [update-index.json](update-index.json)、来源登记和主题索引比较，过滤已处理的同源切片和转载；日期不明就保留未知，不能仅按搜索排序称其“最新”。
3. 能读到正文/转录才提炼具体观点、条件与反例；只有标题则存研究线索，不能据标题修改实践规则。意见修订保留新旧判断，不覆盖原始出处。
4. 判断新增属于：新主题、已有主题的解释、观点修订、社区独立延伸、传播梗。只有会改变回答或行动时才修改对应实践模块；热度不能证明效果。

## 写回（本轮自动执行）

用户请求应用这个可更新 Skill，即可在自己的可写副本中维护来源和模块，不另询问普通本地记录写入。用户已有知识库时同步其相关主题笔记；没有指定知识库就更新 Skill 副本。公共仓库的推送和公开发布遵从该次任务已有授权。

记录可使用随包脚本：

```text
python3 scripts/update_skill.py --input 本轮记录.json --checked-at YYYY-MM-DD
```

最小记录字段：`url`、`author`、`title`、`published_at`（未知为 null）、`kind`（original/community/meme）、`coverage`（title/description/transcript/full）、`summary`、`impact`。摘要用自己的话；不保存私密数据、凭据、全文字幕或课程。

需要同步实践模块时附 `module_changes`：每项包含 `path`（只允许现有 references/*.md）、`before`（唯一旧段落）、`after`（新段落）。Agent 先读原段落，确认来源覆盖足够，再写精准修改。脚本会校验路径和旧段落、保存变更摘要及前后哈希；失败不写半套文件。低覆盖材料不能携带模块修改。

脚本会维护来源登记的增量区、索引记录与 [latest-updates.md](latest-updates.md)。同一 URL、内容和覆盖程度的重读不会重复入库；再次核对仍更新检查日期。主题新增或归并由 Agent 同步 [topic-map.md](topic-map.md)，不将每个帖子自动算作一条新理论。

完成后用短话说明“发现什么 → 更新了哪里 → 未核对什么”。没有新内容就说本轮没有需改动之处；查询失败不能报告“没有新内容”。

## 直接使用

```text
用 $sun-alan-life-lab，根据我的现状帮我开始行动；先检查他们有没有值得更新的新观点。
```

```text
用 $sun-alan-life-lab 检查孙哥和邵艾伦的新内容，核对后更新这个 Skill 和我的知识库，再说明有什么变化。
```

```text
用 $sun-alan-life-lab 把这条新的原始链接加入知识库：〔URL〕。比较旧观点，必要时更新相关练习。
```
